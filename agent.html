A2A over MQTT · broker neutral

跨框架的 Agent 发现与任务交换

一套 broker 中立的 A2A over MQTT 契约，兼容 EMQX A2A Registry 与 A2A 1.0 分层规范。主题名、MQTT 5 属性映射与载荷格式都是可评审、可互操作的开放约定。

查看主题契约 阅读规范原文 ↗
Topic contract

主题命名空间

所有 A2A 主题位于保留前缀 $a2a/ 之下，必须使用显式 filter 订阅，不受普通 # / + 通配符影响。

用途主题说明
Agent 发现$a2a/v1/discovery/{org}/{unit}/{agent}保留消息承载 Agent Card；QoS 1 + RETAIN；空载荷注销
任务请求$a2a/v1/{org}/{unit}/{agent}/requestsQoS 1；携带 Response Topic 与 Correlation Data
状态流$a2a/v1/{org}/{unit}/{agent}/tasks/{id}/status进度与终态事件，供订阅而非轮询
工件流$a2a/v1/{org}/{unit}/{agent}/tasks/{id}/artifactsArtifact 形式的任务输出，与 Message 分离
收件箱$a2a/v1/{org}/{unit}/{agent}/inbox可选的通用响应主题
工作池$share/{pool}/$a2a/v1/{org}/{unit}/{agent}/requests多个 worker 共享订阅，轮询分发，每条恰好一次
注册时，完整三段地址 {org}/{unit}/{agent} 必须等于发布客户端的 Client ID，不一致会被 PUBACK / PUBREC 拒绝（原因码 0x87）。
MQTT 5 mapping

不发明新传输协议，只把 A2A 概念映射到 MQTT 5 已有字段。

A2A 概念MQTT 5 载体
请求 / 响应配对Response Topic + Correlation Data
Agent 可用性a2a-status = online / offline / lwt
状态来源a2a-status-source = broker / agent / lwt

Task exchange

一次 message/send 的完整时序

请求走 QoS 1，状态与工件分流推送，终态自动关流。

sequence · message/send复制
Client        Gateway       Broker        Agent
  │              │             │             │
  │─ POST ──────▶│             │             │  1 Bearer token
  │              │─ PUBLISH ──▶│             │  2 /requests, QoS 1
  │              │◀─ PUBACK ───│             │  3 语义错误在此确认
  │              │             │─ dispatch ─▶│  4 $share 轮询
  │              │             │◀ status=WORKING
  │◀─ SSE ───────│◀────────────│             │  5 状态流
  │              │             │◀ artifacts  │  6 Artifact 主题
  │◀─ SSE ───────│◀────────────│             │  7 工件流
  │              │             │◀ completed  │  8 终态
  │◀─ close ─────│             │             │  9 自动关闭 SSE
Agent state

在线状态：三个值，三种来源

显式断开、异常断开与 Broker 侧决策被明确区分，避免「已注册即在线」的误判。

offline / broker

已注册但当前不在线；Card 仍作为保留消息存在，可被发现。

source = broker

online / agent

客户端连接建立且 Agent Card 校验通过后进入在线状态。

source = agent

lwt / lwt

异常断开由 MQTT 遗嘱消息标记，与主动离线区分，便于上层调度。

source = lwt
Security

身份、签名与零回归

身份绑定在连接层，Card 签名可选校验，所有 A2A 特性默认关闭。

请求身份绑定

三档策略 off / caller / agent_or_gateway；拒绝时 PUBACK 携带 UnauthorizedError。

a2a_request_auth

Card JWS / JWKS

支持 RS256 / ES256，JKU allowlist；签名覆盖规范化 Card，保留未知扩展字段。

RS256 / ES256

默认零回归

关闭 A2A 时普通 MQTT 行为与性能不变；Registry 禁用态在所有 Hook 上为 no-op。

opt-in by default

HTTP gateway

让标准 SDK 只改一个端点

网关暴露 POST /a2a/v1/{org}/{unit}/{agent}，把 JSON-RPC 请求桥接到 MQTT。

curl · message/send via gateway复制
$ curl -X POST http://localhost:18083/a2a/v1/acme/fleet/router-agent \
  -H "Authorization: Bearer my-secret-token" \
  -H "Content-Type: application/a2a+json" \
  -d '{
    "jsonrpc":"2.0", "id":1,
    "method":"message/send",
    "params":{ "message":{ "role":"user", "parts":[{"kind":"text","text":"检查路由状态"}] } }
  }'

# 网关把请求映射到 $a2a/v1/.../requests，
# 并用 Response Topic + Correlation Data 配对响应。
生产环境请在 a2a_gateway.tokens 配置 Bearer token；principal 会升格为 MQTT CONNECT 用户名，与请求身份绑定策略联动。
